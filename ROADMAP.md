## Модельная стратегия (уже в v1.0-beta)

Ассистент автоматически выбирает модель по цепочке `LLM_MODEL` → `LLM_FALLBACK_MODELS`
(модели без API-ключа пропускаются). Приоритет по умолчанию:

| Приоритет | Модель                          | Когда использовать              |
|-----------|---------------------------------|---------------------------------|
| 1         | GPT-5 / Claude / Gemini         | если есть API и бюджет          |
| 2         | Nemotron 120B Free (OpenRouter) | пока не исчерпан бесплатный лимит |
| 3         | Локальная llama3.2 (Ollama)     | всегда доступна                 |
| 4         | Понятное сообщение пользователю | если ни одна модель недоступна  |

## Монетизация (обсуждение)

| Режим       | Цена    | Что даёт                                        |
|-------------|---------|-------------------------------------------------|
| **Local Mode** | бесплатно | локальная модель (Ollama), базовые инструменты  |
| **Cloud Mode** | подписка  | мощные модели, продвинутая память, приоритет    |

Открытые вопросы: как считать лимиты (токены/запросы), нужен ли пробный
период, реферальная программа.

## Путь к v1.0.0 — этапы развития (личность и целостность)

> Решение от 2026-08-07: не раздувать ядро 50 фичами. Сначала превратить
> FOL из «набора инструментов» в цельного помощника. Каждая идея проходит
> гейты: **пользовательская оценка → дизайн → реализация**.

### Этап 0: Personality ✅ (реализован, ожидает оценки)
- Слой `fol/modules/llm/personality.py` — естественные контекстные ответы вместо
  «Done.»/«Готово.»/«OK» (JARVIS-стиль, лёгкий юмор, язык пользователя).
- Внедрён в финальный слой ответов FOL + во все system prompt (engine/prompt_manager/agent/orchestrator).
- 50 тестов; FOL 251 passed, корневые 954 passed, Swift build ✅.
- **Следующий шаг: оценка после живого использования.**

### Этап 1: Context Conversation ✅ (реализован 2026-08-10)
- FOL помнит контекст разговора:
  > «Найди новости про OpenAI» → «А какая из них самая важная?» → FOL понимает, что речь всё ещё про OpenAI.
- Схема: разговор → понимание контекста → действие → естественный ответ (вместо команда → действие → Done).
- Реализация: `ContextManager.is_follow_up()` (RU+EN детекция продолжений, защита от ложных «А …»-переходов) + `get_current_topic()` (извлечение сущностей) + `get_follow_up_context()` (блок привязки) → подключается и в `Orchestrator._assemble_context()`, и в живой путь `FOL._get_context()`.
- 46 новых тестов (`fol/tests/core/test_context_conversation.py`, `test_final_response.py`); FOL 485 passed.
- **Следующий шаг: оценка после живого использования, затем Этап 2 (Режимы работы).**

### Этап 2: Режимы работы ✅ (реализован 2026-08-10)
| Режим | Что это |
|-------|---------|
| **Companion** | Обычный разговор (по умолчанию) |
| **Assistant** | Выполнение задач на Mac |
| **Agent** | Сложные многошаговые задачи |
| **Focus** | Минимум разговоров, максимум действий |
- Переключение голосом: «FOL, режим Focus» — работает и текстом: «режим фокус» / «focus mode» / «режим фокуса пожалуйста».
- Активный режим передаётся в контекст LLM (`CURRENT MODE: …`), виден в `status`.
- 36 новых тестов (`fol/tests/core/test_modes.py`); FOL 521 passed.
- **Следующий шаг: Этап 3 (Screen Awareness — фундамент уже есть) или Этап 5 (Proactive Mode, высокий приоритет).**

### Этап 3: Screen Awareness 🚧
- «FOL, что сейчас у меня на экране?» → «У тебя открыт VS Code. В редакторе `orchestrator/server.py`, терминал показывает сервер на 8420.»
- Фундамент уже есть: `context_engine/` (app_monitor + browser_url + snapshot) + screenshot tools.

### Этап 4: Memory 2.0 🚧 (фундамент готов)
- Структурированная память поверх Obsidian:
  - **Facts** — «Пользователь работает над FOL»
  - **Preferences** — «Предпочитает короткие ответы»
  - **Projects** — «FOL → v1.0-beta»
  - **Goals** — «Выпустить v1.0.0»
  - **Relationships** — «Преподаватель → email → …»
- Фундамент: 6-layer memory (identity/preferences/relationships/episodic/Obsidian).

### Этап 5: Proactive Mode 🚧 (высокий приоритет)
- Не ждать команд: «Ты почти час работаешь над кодом. Сделать перерыв?» / «Ты собирался отправить отчёт. Напомнить через час?»
- **Обязательно ON/OFF-тумблер**, чтобы не превратиться в назойливого ассистента. 😄
- Фундамент: `suggestion_engine.py`, ambient loop, daily tracker.

### Этап 6: «Do what I mean» 🚧 (настоящий агент)
- «Подготовь всё к релизу FOL» → FOL сам: git → тесты → незакоммиченные изменения → VERSION → .app → .pkg → результат.
- **Опасные действия — только после подтверждения пользователя.**

### Идея: один FOL с двумя гранями
- **Рабочий FOL:** «Проверил тесты. 902 passed. Сборка успешна.»
- **Личный FOL:** «Ты уже третий час сидишь над FOL. Может, хотя бы воды выпьешь?»
- Это **один и тот же FOL**, который понимает контекст, а не два разных бота. → В этом суть FOL.

## v2.0 — идеи

### P0 — фундамент
1. **Cloud Sync** — синхронизация памяти (Obsidian / эпизодическая) между устройствами.
2. **Knowledge Graph** — граф связей: люди, проекты, события; умные подсказки на основе связей.

### P1 — расширение
3. **Plugin SDK** — публичный API для сторонних плагинов (стабильный контракт инструментов).
4. **Workflow Builder** — визуальный конструктор многошаговых сценариев (триггер → действия).

### P2 — охват
5. **Mobile Companion** — iOS/Android клиент для общения с ассистентом с телефона (через bridge).
